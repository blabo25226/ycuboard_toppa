# コマンドと動作の仕様

すべて `python -m src.main <オプション>`（リポジトリのルートで実行）。

## コマンド
| 目的 | オプション |
|---|---|
| ID・パスワードを対話入力して `id_password.txt` を作る | `--init` |
| 環境の診断（OS・Python・Playwright・認証情報・ログイン履歴・自動起動。秘密は出さない） | `--doctor` |
| 保存済みセッションで自動ログインできるか確認 | `--check-login` |
| Teams（SharePoint）に入れるか・履修講義のチームが見つかるか確認 | `--check-teams`（承認が要るときは `--headful` を付ける） |
| 自分宛にテストメールを送る（ログイン済みが前提） | `--test-mail` |
| ログイン（初回・セッション切れ。ブラウザを表示） | `--login` |
| 初回監査（予行: 保存される資料の一覧だけ表示） | `--initial-sync --dry-run` |
| 初回監査（公開済みの資料を保存し、全講義の現状を基準として記録） | `--initial-sync` |
| **今すぐ監査する**（定期チェックの ON/OFF に関係なく実行。ダウンロード・メールは設定に従い、結果を画面にも表示） | `--now`（`--once` と同じ） |
| 〃 + 対象講義の資料も保存（ダウンロードが OFF のとき） | `--now --with-download` |
| 〃 講義を一時的に指定（config を上書き） | `--now --with-download --course 統計モデリング1`（複数回指定可） |
| メールを送らずに試す | `--no-mail` |
| ブラウザを表示して実行 | `--headful` |
| Teams の講義資料も確認・保存する / やめる | `--teams-on` / `--teams-off` |
| 設定した時刻に自動実行する常駐 | `--watch` |
| Windows ログオン時に `--watch` を自動起動 / 解除 | `--install-task` / `--uninstall-task` |
| 履修講義の一覧 / 現在の設定 | `--list-courses` / `--status` |
| 定期監査の健康診断（常駐・自動起動・ログイン・取りこぼし。問題があれば終了コード 1） | `--health` |
| 常駐の起動 / 停止（画面なし。起動済みなら何もしない） | `--start` / `--stop` |

## ON / OFF（初期値: チェック OFF・ダウンロード OFF・メール ON）
- `--check-on` / `--check-off`: 定期チェック。
- `--download-on` / `--download-off`: チェックで見つかった差分の自動ダウンロード。**定期実行ではチェック ON が前提**。
- `--teams-on` / `--teams-off`: Teams（SharePoint）の講義資料の確認。初期 OFF。保存は `--download-on` と対象講義（`--set-courses`）に従う。
- `--mail-on` / `--mail-off`: 結果メール。
- `--mail-always`（初期）/ `--mail-changes-only`: 毎回送る / 更新・保存・エラーがあったときだけ送る。
- `--on` / `--off`: チェックとダウンロードをまとめて切り替える（メールは変えない）。

## 設定
- `--set-times 11:00 17:00 21:30`: 巡回時刻（HH:MM、回数自由。初期 11:00 / 17:00）。
- `--jitter-on`（初期） / `--jitter-off`: 実行時刻の誤差。ON のとき、設定時刻の **±10分** の範囲で、実行のたびに違う時刻にずらす（`jitter_max_minutes`、標準偏差 `jitter_sigma_minutes`=4 分の正規分布を範囲で切り詰め）。全員が同時刻にアクセスして大学のサーバーに負荷が集中するのを避けるため。
- `--set-courses A B`: ダウンロード対象講義（部分一致）。引数なしで全講義。初期は全講義。
- `--set-output フォルダ`: 保存先（初期 `output/`。次回起動から有効）。
- `--set-mail-to アドレス`: 結果メールの宛先（初期は本人の学内アドレス）。
- 設定は `config.json`（git 管理外）。無ければ既定値で動く。キーは `src/config.py` の `DEFAULT_CONFIG` を参照。
- 講義名の照合は、全角半角・空白・括弧・ローマ数字/算用数字の違いを吸収する（「統計モデリングI」= `統計モデリング1`）。

## 認証情報（id_password.txt）
4行: `id` / ID / `password` / パスワード。ID は `@yokohama-cu.ac.jp` を省略可（自動補完）。見出し行や `id:` 接頭辞は省略可。

## 今すぐ監査（--now）
学生が希望したときに、すぐ1回監査する。定期監査が OFF でも実行できる。ログイン → 全講義の教材・テスト・課題の差分チェック → （ダウンロードが ON なら）対象講義の保存 → （メールが ON なら）結果メール、までを定期監査と同じ流れで行い、結果を画面にも表示する（メールと同じ内容と、メールを送ったかどうか）。
- 設定に従う: ダウンロードは `download_enabled`（OFF のときは `--with-download` で今回だけ保存）、メールは `email_enabled` / `email_only_on_change`。メールを送りたくないときは `--no-mail`。
- 初回監査（`--initial-sync`）との違い: 初回監査は、定期監査の前に公開済みの資料を取得して基準を作る手順。`--now` は、基準ができたあとに「今すぐ差分を調べる」もの。基準が無い講義は、初めて見るので差分としては通知しない（記録のみ）。
- 定期監査の最終実行の記録（`--status`）も更新される。

## Teams の講義資料（--teams-on）
履修講義ごとのチームの、チャンネル「一般」→「共有済み」にあるファイル（SharePoint の `Shared Documents/General`）を対象にする。YCU-Board と同じログイン（保存済みセッション）を使い、追加の認証は要らない。
- **チームの対応づけ**: チーム名の全体、または区切り（`_`・空白・`【】` など）で分けた一部が、年度の表記（`R8`・`2026年度` など）を除いて講義名と一致するチームだけを使う。部分一致（「データサイエンス1」と「データサイエンス10」など）は使わない。年度の表記があって今年度（4月始まり）でないチーム（昨年度のチーム）も使わない。候補が複数あれば、今年度の表記があるもの → 短い名前の順。一度決めたチームは、候補に残っている限り使い続ける。
- 対応するチームが変わったとき（前回のチームが候補から外れたなど）は、その講義の Teams の記録をやり直す（新しいチームの中身は初回登録。通知しない）。結果メールの「Teams のお知らせ」に載る。
- フォルダ構成は講義ごとに違う（`講義資料/`、`260925_01` のような日付フォルダ、資料なしなど）。そのため、フォルダ名には依存せず `General` 配下を再帰的に読み、ファイルの追加・更新・削除を差分として扱う。チャンネルのフォルダがまだ無いチーム（誰もファイルを置いていない）は0件として扱う（前回ファイルがあったのにフォルダが無いときだけエラー）。
- **除く**: `Recordings`（会議の録画。大きすぎる）と `*.loop`（Teams が自動で作る部品）。200 MB を超えるファイルは保存せず、結果メールと初回監査の表示で知らせる。
- **初回監査**: 対象講義の `General` 配下を全部保存し、現状を基準として記録する。**定期監査**: 新しく増えたファイル（新規フォルダの中身を含む）を保存する。更新されたファイルは旧版を `<名前>_旧版YYYYMMDD-HHMMSS.<拡張子>` に残して保存し直す。名前変更・移動されたファイルは新しい名前・場所に保存し直す（元の場所には旧版が残る）。削除はローカルに残す。
- 保存先: `<保存先>/<講義名>/Teams/<General からのフォルダ構成>/`。
- 結果メールの「Teams:」欄に、確認した講義数・新規・更新（名前変更・移動を含む）・削除を載せる。日付はこの PC の時刻（日本時間）。チームが無い講義は対象外で、ログにだけ残る。
- Teams の失敗（ログイン・取得）は YCU-Board のチェックを止めず、エラーとして報告する。
- **Teams にログインできなかったとき**: 結果メールの冒頭に、その旨と対処（`--check-teams --headful` で承認）を載せる。定期実行ならトースト通知も出す。`--mail-changes-only` のときは、これだけを理由にしたメールは**復旧するまで1回だけ**（`data/state.json` の `teams_login_failed` / `teams_login_alert_sent`）。復旧後の最初の結果メールに「復旧しました」と載る。`--status` にも表示される。パスワードは1回しか送信しない。

## 初回監査（--initial-sync）
定期監査の前に行う。定期監査は前回との差分だけを見つけるため、設定した時点ですでに公開されている資料を先に取得し、全講義の現状を基準（`data/history.db`）として記録する。
- 保存対象は `target_courses`（`--course` で上書き可）。Teams が ON なら、Teams の資料も同じ対象講義で保存する。`download_enabled` が OFF のときは保存せず記録だけ行う。
- `--dry-run` は何も保存せず（資料も履歴DBの記録も変えない）、保存される資料の一覧と件数だけ表示する（本実行の前に必ず見せる）。
- 結果メールは件名が「初回監査完了」になる。`--no-mail` で送らない。
- 完了すると `data/state.json` に記録され、`--status` の「初回監査」が「完了」になる。ダウンロード対象の講義を増やしたときも再実行する（追加した講義の公開済み資料を取得する）。
- 中断・エラー後に再実行しても、保存済みの資料は再取得されない。

## 1サイクルの動作
1. ブラウザ（Playwright の永続プロファイル `data/auth_profile`）で YCU-Board にアクセスし、必要なら Microsoft SSO を自動で通過する（メール入力→パスワード→「サインイン状態を維持」→Yes）。Authenticator の承認が要る場合は本人の操作を待つ。
2. 時間割（`/lms/timetable`）から履修講義を取得し、各講義ページ（`/lms/course?idnumber=…`）の「教材」欄を読む。
3. 前回の記録（`data/history.db` の `materials` テーブル）と比較する。
   - 新規: 新しい `resource_id`。
   - 更新: 登録日・ファイル名・資料タイトルの変化。同じ資料・同じファイル名で ID だけ変わった場合（再アップロード）は「差し替え」（更新扱い。旧版を退避して同じ名前で保存し直す）。
   - 削除: 消えたもの（ローカルのファイルは残す）。
   - 講義を初めて見たときは「初回登録」として記録のみ。差分としては扱わない。
   - 前回あった資料が0件として読み取られたときは、読み込み失敗の可能性があるので1回だけ読み直してから判定する。
   - 時間割から講義を1件も読み取れなかったときは「成功・更新なし」ではなくエラーとして報告する。
4. 対象講義の「未保存・ローカル消失・更新あり」の資料を `<保存先>/<講義名>/<資料タイトル>/` に保存。更新時は旧版を `<名前>_旧版YYYYMMDD-HHMMSS.<拡張子>` に残す（ダウンロード成功後に退避）。講義名・資料タイトルのフォルダ名は50文字、ファイル名は100文字までに切り詰める。
5. 結果（講義ごとの差分・保存ファイル・エラー）をメール送信し、保存ごとに Windows のトースト通知を出す。

## ログインできなくなったとき（定期実行のみ）
- パスワードは1回だけ送信する。「パスワードが違う」と表示されたら再送信せず失敗にする（誤ったパスワードの連続送信でアカウントがロックされるのを防ぐ）。
- Windows のトースト通知を出し、結果メールが ON ならお知らせメールを**復旧するまで1回だけ**送る（`data/state.json` の `login_alert_sent`）。復旧後の最初の結果メールに「復旧しました」と載る。
- 制約: メールは Outlook on the web 経由のため、Microsoft 側のサインインが切れているとメール自体が送れない。送れなかった場合は次回も再試行する。確実なのはトースト通知と `--status`（最終実行・ログイン失敗の表示）。
- 手動の `--now`（`--once`）では通知しない（本人が画面を見ているため）。

## 常駐（--watch）の挙動
- 20秒ごとに起きて設定を読み直す。ON/OFF・時刻の変更は再起動なしで反映される。
- 設定時刻に誤差（既定 ±10分）を加えた「予定」の時刻になったら1回実行（同じ日の同じ時刻には1回だけ）。誤差は予定ごとに一度だけ決めて `data/state.json` に保存する（再起動しても同じ。前回の同じ枠と同じ値にはならない）。誤差 OFF なら設定時刻ちょうど。起動前に過ぎていた時刻は実行しない。起動後にスリープ等で遅れた場合は、2時間以内なら実行する。2時間を超えたら見送り、`data/state.json` の `skipped_slot` に記録する（`--health` はこれを「固まっている」と見なさない）。
- 毎週火曜 1:00〜6:00 は YCU-Board のメンテナンスのため巡回しない。
- 起動直後に、直近の予定を取りこぼしている（最終実行がその予定より前）なら、1回だけ即実行して補う。メンテナンス中の予定は取りこぼしに数えない。
- 二重起動はしない（すでに常駐があれば終了する）。
- ネットワーク障害などで巡回自体が失敗した場合も、最終実行を「一部エラー」として記録し（`--health` に「前回のエラー」として表示）、トースト通知を出す。
- ログは `logs/ycuboard.log`。

## メール送信
学内 Microsoft 365 は SMTP 基本認証が使えない。既定（`email.method: auto`）は、ログイン済みブラウザで Outlook on the web の作成画面を開き、本文を入力して送信する。追加設定は不要。SMTP を使うなら `email.method` を `smtp` にして `smtp_password.txt` にアプリパスワードを置く。送信に失敗しても巡回は止まらず、ログに残る。

## 対象範囲
- **教材**: 差分の検出と、対象講義のダウンロード。
- **テスト・課題（提出物）**: 追加・更新・削除の**通知のみ**。ダウンロードも提出もしない。講義ページの「テスト」「課題」の一覧を読み取り、前回と比べて、結果メールに1件1文で載せる。
  - 例: `統計モデリングIでテスト:第3回_統計モデリングIが追加されました（解答期間 2026/10/12 11:00 ～ 2026/10/13 00:00）。`
  - 更新の判定はタイトルと期間（解答期間・提出期間）の変化。期間が変わったときは `旧 → 新` を載せる。提出状況（自分が提出したか）は判定に使わない。
  - 講義を初めて確認したとき（初回監査を含む）は、すでにあるテスト・課題は基準として記録するだけで、通知しない。
  - ダウンロードの ON/OFF や対象講義の設定に関係なく、全講義が対象。メールが OFF なら通知もされない。
- 教材のほか、お知らせ・アンケート・掲示板は対象外。

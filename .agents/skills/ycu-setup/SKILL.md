# /ycu-setup — 環境設定

学生（利用者）のPCで、このツールが動く状態を作る。**AI がPCを調べ、結果を学生に見せ、学生が「合っている」と答えてから次へ進む。**

## 進め方のルール
- 1ステップずつ進める。各ステップの最後に「結果の要約」と「次に進んでよいか」を学生に確認する。
- **パスワードをチャットで聞かない・読まない・表示しない。** `id_password.txt` の中身は表示しない（有無・形式の確認は `--doctor` が秘密を出さずに行う）。入力は学生が自分のターミナルで行う（Claude Code なら `!` を付けて `! python -m src.main --init` と案内する）。
- Authenticator の承認など、本人にしかできない操作は代行せず、何をすればよいか具体的に伝える。
- 再開できるようにする。最初に `python -m src.main --doctor` で現状を見て、済んでいるステップは「済んでいます」と伝えて飛ばす（学生が望めばやり直す）。
- 失敗したら、原因の候補を1〜2個に絞って伝え、直してから同じステップをやり直す。先へ進まない。
- コマンドはリポジトリのルートで実行する。選択肢を出せるツール（Claude Code の AskUserQuestion など）があれば使う。
- 学生の言葉づかいに合わせ、専門用語は避ける。

## ステップ

### 1. Python と必要なもの
`python --version` を実行する（動かなければ `py --version`）。
- **3.10 以上** → 次へ。
- **無い／古い** → https://www.python.org/downloads/ から入れてもらう。インストーラの **「Add python.exe to PATH」にチェック**し、入れたらターミナルを開き直してもらう。確認できるまで先へ進まない。
- Python が動くと分かったら: `pip install -r requirements.txt` と `playwright install chromium` を実行する（所要数分。ダウンロードが走ることを伝える）。
- 最後に `python -m src.main --doctor` を実行し、OS / Python / Playwright が OK であることを確認する。OS が Windows 以外なら、未対応であることを伝えて終了する。

### 2. ID とパスワード
`--doctor` の「認証情報」の行を見る。
- **OK**（`ID: d244****@yokohama-cu.ac.jp / パスワード: 記入あり`）→ 学生に「このIDで合っていますか」と確認する。違えば `--init` で上書きしてもらう。
- **NG（ファイルが無い／読めない）** → 学生に説明する: 「ID（`@yokohama-cu.ac.jp` より前の部分。例: `d123456a`）とパスワードを、あなたのPCの `id_password.txt` にだけ保存します。外部には送りません。」そのうえで、**学生自身のターミナルで** `python -m src.main --init` を実行してもらう（または手順どおり4行のファイルを作る）。
- 記入後に `--doctor` をもう一度実行して OK を確認する。
- `id_password.txt` は git に入らない設定済みであること、他人に見せないことを伝える。

### 3. YCU-Board へのログイン（初回と2回目）
`--doctor` の「ログイン履歴」で分岐する。**「初回ログイン」と「保存済みセッションでの2回目以降のログイン」の両方ができることを確認する。**

- **履歴なし（初回）**
  1. `python -m src.main --login` を実行する。ブラウザが開き、ID・パスワードが自動入力される。
  2. Authenticator の承認が求められたら、画面の番号をスマホのアプリに入力してもらう（番号は画面とターミナルに出る）。
  3. 「ログインに成功しました」を確認する。
  4. 続けて `python -m src.main --check-login` を実行する。ブラウザを起動し直しても、人の操作なしでログインできれば **2回目も OK**。
- **履歴あり（最初から2回目）**
  1. まず `python -m src.main --check-login` を実行する。OK なら「すでにログイン済みで、2回目以降の自動ログインもできています」と伝えて次へ。
  2. NG なら（承認の期限切れなど）`--login` で入り直し、もう一度 `--check-login` で確認する。
- **それでも NG** → 原因の候補を伝える: ① ID/パスワードの誤り（→ ステップ2へ戻って直す）、② 承認が間に合わなかった（→ `--login` をやり直す）、③ 大学側のメンテナンス（火曜 1:00〜6:00）。直したら同じステップをやり直す。

### 4. メールの確認
**ログイン済みであること（ステップ3）が前提。** メールは学生の Outlook（大学のメール）から自分宛に送るため。
1. `python -m src.main --test-mail` を実行する。宛先は ID のメールアドレス（`<ID>@yokohama-cu.ac.jp`）。
2. 学生に「Outlook または大学のメールに『[YCU-Board] テストメール』が届きましたか」と聞く。1分ほど待つよう伝える。迷惑メールフォルダ・「その他」タブも見てもらう。
3. **届いた** → 次へ。
4. **届かない** → 送信エラーの表示を確認し、`--test-mail` をもう一度試す。それでも届かなければ、ログイン状態（`--check-login`）を確認する。解決しない場合は、メール機能を OFF にして（`--mail-off`）先へ進んでもよいか学生に聞く（後から `/ycu-config` で変更できる）。

### 5. 履修している講義の確認
1. `python -m src.main --list-courses` を実行する。
2. 結果を番号付きの一覧にして学生に見せ、「**今学期に取っている講義と合っていますか**。足りない／余計なものはありませんか」と聞く。
3. **合っている** → 次へ。
4. **合っていない** → よくある原因を伝える: ① YCU-Board の時間割に講義がまだ載っていない（履修登録・反映待ち）、② 集中講義などが時間割の枠外にある、③ 時間割ページの学期の切り替え。学生にブラウザで YCU-Board の時間割ページを見てもらい、足りないものを教えてもらう。ツール側の不具合が疑われる場合（時間割に載っているのに出ない）は、開発者に報告する旨を伝える（`.agents/architecture.md` を参照）。学生が「この状態でよい」と言えば次へ進む。

### 6. 設定（/ycu-config）
ここまでで環境は整った。続けて **`/ycu-config` の手順**（定期監査の設定と、すでに公開されている資料を取得する「初回監査」を含む）（`.agents/skills/ycu-config/SKILL.md`）を実行する。学生が後にしたいと言えば、いつでも `/ycu-config` で設定できることを伝えて終了する。

## 終わりに
次を短くまとめて伝える。
- 確認できたこと（Python、ID、ログイン（初回・2回目）、メール、履修講義 N 件）。
- 設定が済んでいなければ `/ycu-config` を勧める。
- ログインが切れたら `python -m src.main --login`、困ったら README の「困ったとき」を見ること。

## 追加で確認するとよいこと（学生が必要なら）
- 保存先フォルダ（初期は `output/`）。クラウド同期フォルダやUSBにする場合は `--set-output`。
- Teams の講義資料（`--teams-on`）。YCU-Board と同じログインで動くので、環境設定の追加は要らない。`/ycu-config` で扱う。
- 自動起動の登録（`--install-task`）。`/ycu-config` の最後で扱う。
- PC がスリープ・シャットダウンしていると定期チェックは動かないこと。
- 毎週火曜 1:00〜6:00 は大学のメンテナンスでチェックしないこと。

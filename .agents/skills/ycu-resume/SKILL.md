# /ycu-resume — 止まった定期監査を再開する

定期監査は、PC の電源が入っていてログオンしている間だけ動く。PC を閉じる・スリープ・シャットダウン・再起動、ログインの期限切れなどで止まることがある。**AI が原因を診断し、直せるものは直し、取りこぼした分を補う。**

## 進め方のルール
- 診断してから直す。原因を決めつけない。
- 本人にしかできない操作（Authenticator の承認など）は代行せず、案内する。パスワードをチャットで聞かない・表示しない。
- 常駐の起動・自動起動の登録・補完の実行（資料が保存される）は、何が起きるかを伝えて**了承を得てから**行う。
- コマンドはリポジトリのルートで実行する。選択肢を出せるツールがあれば使う。

## 1. 診断する
```powershell
python -m src.main --health
```
結果の読み方:
| 表示 | 意味 |
|---|---|
| 定期チェック OFF | 止まっているのではなく、止めている設定。使いたいなら `/ycu-config`（または `--check-on`） |
| 自動起動タスク 未登録 | PC を再起動すると常駐が戻らない |
| 常駐プロセス 動いていません | 定期監査が止まっている（最も多い原因） |
| 最終実行 ログイン失敗 | YCU-Board にログインできていない |
| 取りこぼし | 予定の時刻に実行できていない回がある |

`正常です` と出たら、止まっていない。学生が「更新が来ない」と言っている場合は、`--status` の最終実行と、大学側に実際に更新が無いかを確認する。

必要なら詳しく見る: `python -m src.main --status`、`logs/ycuboard.log` の末尾（PowerShell なら `Get-Content logs\ycuboard.log -Tail 30`）。

## 2. 原因ごとに直す
`--health` が出した問題の順に対処する。1つ直すたびに、次へ進む前に結果を学生に伝える。

### A. ログインできない（最終実行が「ログイン失敗」）
他の対処より先に行う（ログインできないと、起動し直してもまた失敗する）。
1. `python -m src.main --check-login` で状態を確認する。
2. NG なら `python -m src.main --login` を実行してもらう。ブラウザが開き、Authenticator の承認が必要なら、画面の番号を学生がスマホで入力する。
3. もう一度 `--check-login` で OK を確認する。
4. それでも NG なら、パスワード変更の可能性を伝え、学生自身のターミナルで `python -m src.main --init` を実行して `id_password.txt` を更新してもらい、手順 1 からやり直す（`/ycu-setup` のステップ 2・3 を参照）。

### B. 常駐が止まっている
1. 「定期監査を起動し直します。画面は出ません」と伝え、了承を得る。
2. `python -m src.main --start` を実行する。自動起動が登録済みならそのタスクを開始し、未登録なら画面なしで直接起動する。
3. 起動後に自動で「取りこぼし」を検出し、必要なら**起動直後に1回補完する**ことを伝える（C は多くの場合これで済む）。
4. `python -m src.main --health` で `常駐プロセス 動作中` を確認する。

### C. 取りこぼしを補う
常駐を起動した（B）後に、まだ `取りこぼし` と出るとき、または常駐を使わず補いたいとき。
1. 「確認を1回実行します。自動ダウンロードが ON なら、新しい資料が保存され、結果メールが届きます」と伝え、了承を得る。
2. `python -m src.main --once` を実行する（メールを送らないなら `--no-mail`）。
3. 結果を学生に見せる: 確認した講義数、新規・更新された資料、保存したファイル、エラー。
4. 初回監査が済んでいない場合（`--status` の「初回監査」が「未実施」）は、先に `/ycu-config` で初回監査を行うよう案内する。

### D. 自動起動が未登録
PC を再起動すると常駐が止まったままになる原因。
1. 「Windows にログオンするたびに自動で常駐を開始するよう登録します」と伝え、了承を得る。
2. `python -m src.main --install-task` を実行する。
3. すぐ開始するには `python -m src.main --start`。

## 3. 確認する
```powershell
python -m src.main --health
python -m src.main --status
```
`正常です` を確認し、次を学生に伝えて終わる。
- 直したこと（ログイン・常駐の起動・補完・自動起動の登録）。
- 次の予定時刻（`--health` の「巡回時刻」）。

## 再発を減らすために（学生に伝える）
- **スリープ中・ふたを閉じている間は動かない。** 予定時刻にPCを使うなら、電源設定でスリープまでの時間を長くする、または「ふたを閉じても何もしない」にする（Windows の設定 → システム → 電源とバッテリー）。
- **再起動・シャットダウンしても、自動起動を登録していれば、次にログオンしたとき常駐が戻る**。戻ったとき、取りこぼしを自動で1回補う。
- **PC を長く使わない日は止まる**のが普通。使い始めたときに補われる。
- ログインが切れたときは、Windows の通知と（送れれば）お知らせメールが来る。`python -m src.main --login` で復旧できる。
- 毎週火曜 1:00〜6:00 は大学のメンテナンスで、取りこぼしとは数えない。

## 使うコマンド
| 目的 | コマンド |
|---|---|
| 診断 | `--health` / `--status` |
| ログインの確認・復旧 | `--check-login` / `--login` |
| 常駐の起動 / 停止 | `--start` / `--stop` |
| 取りこぼしを補う | `--once` |
| 自動起動の登録 / 解除 | `--install-task` / `--uninstall-task` |

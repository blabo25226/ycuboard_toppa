# /ycu-resume — 定期監査が止まっていないか確かめ、止まっていれば再開する

定期監査は、PC の電源が入っていてログオンしている間だけ動く。PC を閉じる・スリープ・シャットダウン・再起動、ログインの期限切れなどで止まることがある。

**学生が「止まった」と思っていても、実際は止まっていないことがある**（更新が無いだけ、メールが「更新時のみ」の設定、次の予定時刻がまだ、など）。そのため、**最初に「本当に止まっているか」を判定し、止まっていなければ何も変更しない。** 止まっているときだけ、原因を直して再開する。

## 進め方のルール
- **学生に理由を尋ねず、すぐ診断を始める。** 学生が「メールが来ない」などと言っていれば、2 の表で確かめる手がかりにする。
- 診断してから動く。**止まっていると判定するまで、起動・停止・登録・実行などの変更をしない。**
- 本人にしかできない操作（Authenticator の承認など）は代行せず、案内する。パスワードをチャットで聞かない・表示しない。
- 常駐の起動・自動起動の登録・補完の実行（資料が保存される）は、何が起きるかを伝えて**了承を得てから**行う。
- コマンドはリポジトリのルートで実行する。選択肢を出せるツールがあれば使う。

## 1. 診断して、止まっているか判定する
```powershell
python -m src.main --health
python -m src.main --status
```
`--health` の末尾の **「判定」** を見る。

| 判定の表示 | 意味 | 次の手順 |
|---|---|---|
| `止まっていません。正常に動いています。` | 常駐が動いていて、取りこぼしも無い | **2（止まっていない場合）へ。何も変更しない** |
| `止まっているのではなく、定期チェックを OFF にしています` | 設定で止めている | 2 の「OFF の場合」へ |
| `止まっている、または問題があります。` | 常駐停止・ログイン失敗・取りこぼし・自動起動未登録など | **3（原因ごとに直す）へ** |

予定時刻の直後は「実行中」の可能性がある（判定に注記が出る）。その場合は数分待ってからもう一度 `--health` を実行する。

## 2. 止まっていない場合（変更しない）
**根拠を学生に見せる**: 常駐が動作中であること、最終実行の日時と結果、次の予定時刻。そのうえで、学生が気になった現象を、次の表で確かめる。

| 学生の感じていること | 確認すること | 説明・対処 |
|---|---|---|
| 更新メールが来ない | `--health` のメール設定。迷惑メール・「その他」タブ | 「更新があったときだけ」だと、更新が無ければ来ない。毎回なら `--mail-always`。メール OFF なら `--mail-on` |
| 資料が保存されない | 自動ダウンロード ON/OFF、保存対象の講義（`--status`）、`output/` | その講義が保存対象か、そもそも新しい資料が出ていないか。対象を変えるなら `/ycu-config` |
| 次の確認がまだ | 「次の予定」の時刻 | 予定時刻になるまで動かないのが正常 |
| 更新があるはずなのに検出されない | 大学の画面で実際に資料が更新されているか。`--once --no-mail` を1回実行して結果を見る | 登録日が変わらない差し替えは検出できないことがある。手動で `--once` を実行して確かめる |
| 最終実行が古い | 最終実行と巡回時刻 | 1日2回なら最大で半日あくのが正常 |
| 初回監査をしていない | `--status` の「初回監査」 | 未実施なら `/ycu-config` の初回監査を案内する |

- 手動で確かめたい場合だけ、了承を得て `python -m src.main --once --no-mail` を実行して結果を見せる（自動ダウンロードが ON なら資料が保存されることを先に伝える）。
- **OFF の場合**: 「止まっているのではなく、定期チェックを OFF にしている」ことを伝え、使いたければ `/ycu-config`（または `--check-on`。初回監査が済んでいること）で ON にする。
- 説明しても納得されない／原因が分からない場合は、`logs/ycuboard.log` の末尾（`Get-Content logs\ycuboard.log -Tail 30`）を確認する。

ここで終了する。**止まっていないのに再起動・再登録などをしない。**

## 3. 止まっている場合: 原因ごとに直す
`--health` が出した「問題」の順に対処する。1つ直すたびに、次へ進む前に結果を学生に伝える。

### A. ログインできない（最終実行が「ログイン失敗」）
他の対処より先に行う（ログインできないと、起動し直してもまた失敗する）。
1. `python -m src.main --check-login` で状態を確認する。
2. NG なら `python -m src.main --login` を実行してもらう。ブラウザが開き、Authenticator の承認が必要なら、画面の番号を学生がスマホで入力する。
3. もう一度 `--check-login` で OK を確認する。
4. それでも NG なら、パスワード変更の可能性を伝え、学生自身のターミナルで `python -m src.main --init` を実行して `id_password.txt` を更新してもらい、手順 1 からやり直す（`/ycu-setup` のステップ 2・3 を参照）。

### B. 常駐が止まっている
1. 「定期監査を起動し直します。画面は出ません」と伝え、了承を得る。
2. `python -m src.main --start` を実行する。自動起動が登録済みならそのタスクを開始し、未登録なら画面なしで直接起動する。
3. 起動後に自動で「取りこぼし」を検出し、必要なら**起動直後に1回補完する**ことを伝える（C は多くの場合これで済む）。
4. `python -m src.main --health` で `常駐プロセス 動作中` を確認する。

### B'. 常駐は動いているのに予定が実行されていない（固まっている）
1. 「常駐を一度止めて起動し直します」と伝え、了承を得る。
2. `python -m src.main --stop` → `python -m src.main --start`。
3. `--health` で確認する。繰り返すなら `logs/ycuboard.log` を確認し、原因（ログイン・ブラウザ・ネットワーク）を調べる。

### C. 取りこぼしを補う
常駐を起動した（B）後に、まだ取りこぼしが出るとき、または常駐を使わず補いたいとき。
1. 「確認を1回実行します。自動ダウンロードが ON なら、新しい資料が保存され、結果メールが届きます」と伝え、了承を得る。
2. `python -m src.main --once` を実行する（メールを送らないなら `--no-mail`）。
3. 結果を学生に見せる: 確認した講義数、新規・更新された資料、保存したファイル、エラー。
4. 初回監査が済んでいない場合（`--status` の「初回監査」が「未実施」）は、先に `/ycu-config` で初回監査を行うよう案内する。

### D. 自動起動が未登録
PC を再起動すると常駐が止まったままになる原因。
1. 「Windows にログオンするたびに自動で常駐を開始するよう登録します」と伝え、了承を得る。
2. `python -m src.main --install-task` を実行する。
3. すぐ開始するには `python -m src.main --start`。

## 4. 再確認して終わる（止まっていた場合）
```powershell
python -m src.main --health
```
`止まっていません。正常に動いています。` を確認し、次を学生に伝えて終わる。
- 直したこと（ログイン・常駐の起動・補完・自動起動の登録）。
- 次の予定時刻（`--health` の「次の予定」）。

## 再発を減らすために（学生に伝える）
- **スリープ中・ふたを閉じている間は動かない。** 予定時刻にPCを使うなら、電源設定でスリープまでの時間を長くする、または「ふたを閉じても何もしない」にする（Windows の設定 → システム → 電源とバッテリー）。
- **再起動・シャットダウンしても、自動起動を登録していれば、次にログオンしたとき常駐が戻る**。戻ったとき、取りこぼしを自動で1回補う。
- **PC を長く使わない日は止まる**のが普通。使い始めたときに補われる。
- ログインが切れたときは、Windows の通知と（送れれば）お知らせメールが来る。`python -m src.main --login` で復旧できる。
- 毎週火曜 1:00〜6:00 は大学のメンテナンスで、取りこぼしとは数えない。

## 使うコマンド
| 目的 | コマンド |
|---|---|
| 診断（止まっているかの判定） | `--health` / `--status` |
| ログインの確認・復旧 | `--check-login` / `--login` |
| 常駐の起動 / 停止 | `--start` / `--stop` |
| 取りこぼしを補う・手動で確認 | `--once` / `--once --no-mail` |
| 自動起動の登録 / 解除 | `--install-task` / `--uninstall-task` |

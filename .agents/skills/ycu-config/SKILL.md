# /ycu-config — 利用設定と初回監査

学生に1つずつ尋ねて決め、**選んだ内容をコマンドで反映し、最後に一覧で見せて確認する。** 環境が整っていること（`/ycu-setup`）が前提。

## 全体の流れ
1. 定期監査（ON/OFF・回数・時刻）を決める — ただし **ON にするのは初回監査の後**
2. 講義ごとの自動ダウンロードを決める（Teams の講義資料を含めるかも決める）
3. 結果メールを決める
4. **初回監査**: 定期監査の前に、すでに公開されている資料を取得し、現状を「基準」として記録する
5. 確認と反映（定期監査を ON にする・自動起動の登録）

## なぜ初回監査が必要か
定期監査は「前回からの**差分**」だけを見つける仕組み。ところが、ほとんどの講義では**設定した時点で資料がすでに公開されている**。何もしないと、それらが最初の定期監査でまとめて「新着」になったり、取得されないまま基準になってしまう。そこで、定期監査の前に既存の資料を取得し、全講義の現状を基準として記録しておく。

## 進め方のルール
- まず `python -m src.main --doctor` を実行する。必須項目が NG なら、先に `/ycu-setup`（`.agents/skills/ycu-setup/SKILL.md`）を勧めて終了する。
- 最初に `python -m src.main --status` で**現在の設定**を学生に見せる。変えたくない項目は触らない。
- 質問は1回に1項目。各項目の選択肢と初期値を示す。選択肢を出せるツール（Claude Code の AskUserQuestion など）があれば使う。
- 設定は `config.json` を直接編集せず、必ず `python -m src.main --…` で反映する（入力の検証が入る）。
- 講義名は `--list-courses` に表示された名前をそのまま使う。スペースや括弧を含む名前は `"…"` で囲む。
- 永続的な変更（定期監査の ON、自動起動の登録）と、保存を伴う操作（初回監査の本実行）は、学生の了承を得てから行う。

## 1. 定期監査（定期チェック）
「決まった時刻に YCU-Board を自動で見に行き、資料の更新を調べる機能」と説明する。**初期は OFF。**

1. **使うか**を聞く。使う → ステップ 2 以降も進める（`--check-on` は**ステップ 5 で**反映する）。使わない → `--check-off` にして、「自動では確認しません。必要なときだけ手動で確認できます」と伝える。
2. 使うとき、**1日に何回、何時に確認するか**を聞く。
   - 初期は 1日2回（11:00 と 17:00）。「朝・昼・晩」のような答えは時刻にして復唱する（例: 8:00 / 12:30 / 19:00）。
   - 回数は自由だが、**1日1〜4回程度**を勧める（大学のサーバーに負荷をかけないため。多くても6回まで）。
   - `--set-times 8:00 12:30 19:00` のように反映する（HH:MM、複数可）。
   - 伝えること: PC の電源が入っていてログオン中のときだけ動く。毎週火曜 1:00〜6:00 は大学のメンテナンスで確認しない。
3. **実行時刻に誤差を入れるか**を聞く。**初期は ON。**
   - 説明: 「設定した時刻の前後 **±10分** の範囲で、実行のたびに違う分・秒にずらします（例: 11:00 の設定なら 10:52 や 11:06 に実行）。全員が同じ時刻にアクセスして大学のサーバーに負荷が集中するのを避けるためです。OFF にすると設定した時刻ちょうどに実行します。」
   - 誤差ON → `--jitter-on`（初期）／ 誤差OFF → `--jitter-off`。
   - 誤差の大きさ（±10分、標準偏差4分）を変えたい人は、`config.json` の `jitter_max_minutes` / `jitter_sigma_minutes` で調整できる（通常は変えない）。

## 2. 講義ごとの自動ダウンロード
「定期監査で**資料に差分（新しい資料・更新）があったとき**、その資料を自動でPCに保存するか」を、**講義ごとに**決める。（確認自体は全講義で行い、メールで報告される。保存するかどうかだけを選ぶ。）

1. `python -m src.main --list-courses` で履修講義を取得し、番号付きで学生に見せる。
2. 「自動で保存したい講義の番号を教えてください（複数可／`全部`／`なし`）」と聞く。**講義を1つずつ確認する形でもよい**（数が多ければ番号でまとめて聞く）。選んだ内容は復唱して確認する。
3. 反映する。
   - 一部の講義 → `--set-courses "講義名1" "講義名2"` と `--download-on`
   - 全部 → `--set-courses`（引数なし）と `--download-on`
   - なし → `--download-off`
4. 学生に伝えること:
   - 保存先は `output/<講義名>/<資料タイトル>/`。更新されたファイルは旧版も残る。
   - 保存先を変えたい場合は `--set-output "D:\講義資料"`（次回起動から有効）。**初回監査の前に決める。**
   - ダウンロードの対象は「教材」の資料のみ。テスト・課題（提出物）は保存も提出もしないが、**追加・更新・削除はメールで知らせる**（この選択とは関係なく全講義が対象）。
5. **Teams の講義資料**も確認・保存するかを聞く。**初期は OFF。**
   - 説明: 「講義によっては、YCU-Board ではなく Teams（チャンネル『一般』→『共有済み』）に資料が置かれます。ON にすると、履修講義のチームにあるファイルも同じように確認し、保存します。」
   - 使う → `--teams-on` ／ 使わない → `--teams-off`。保存するかどうかと対象の講義は、上のステップ 2 の選択（自動ダウンロード・対象講義）に従う。
   - 伝えること: 保存先は `output/<講義名>/Teams/…`。会議の録画（`Recordings`）は大きいので保存しない。Teams にチームが無い講義は対象外。YCU-Board と同じログインで動き、追加の承認は通常要らない。
   - 定期監査では、新しく増えたファイル（新しいフォルダを含む）が保存される。Teams を使う講義は、**初回監査**で `General` 配下の既存ファイルが全部保存される（機械学習のように写真が多い講義は数十件になる）ので、予行で件数を見せる。

6. **クラウド保存**（PC につないだ Google Drive など）をするかを聞く。**初期は OFF。** 設定の手順は `/ycu-cloud`（`.agents/skills/ycu-cloud/SKILL.md`）。
   - 説明: 「`output/` に保存した資料を、Google Drive for Desktop などでつないだクラウドの指定フォルダにも同じ構成でコピーします。初回監査・定期監査のたびに、足りない分だけコピーします。」
   - 使う → `/ycu-cloud` の手順で進める（つながっているドライブの確認 → 複製先フォルダを学生に聞く（中身は見ない）→ `--set-cloud-dir` → `--test-cloud` → `--cloud-on`）。使わない → `--cloud-off`。後から変えるときも `/ycu-cloud`。
   - 伝えること: Google Drive for Desktop が起動していてドライブが見えていること（見えないときはエラーとして報告され、次回に補う）。複製先に作ったものは消さない。`output/` の中は指定できない。**初回監査の前に決める**と、初回の分もまとめてコピーされる。

## 3. 結果のメール
「定期監査・ダウンロードの結果を、ID のメールアドレス（`<ID>@yokohama-cu.ac.jp`）にメールで送るか」を聞く。**初期は ON。**

1. **送るか**: 送る → `--mail-on` ／ 送らない → `--mail-off`。
2. 送るとき、**頻度**を聞く。
   - 毎回（差分がなくても確認のたびに送る）→ `--mail-always`（初期）
   - 更新・保存・エラーがあったときだけ → `--mail-changes-only`（1日の回数が多いときに勧める）
3. **宛先**: 初期は ID のアドレス。別のアドレスにしたい場合は `--set-mail-to アドレス`。
4. メールに載る内容: 確認した講義の数、新しい資料／更新された資料、保存したファイル、エラー、**テスト・課題の追加・更新・削除**（例: 「統計モデリングIでテスト:第3回…が追加されました」）。
5. **ログインできなくなったとき**のお知らせも、メール ON なら同じ宛先に届く（復旧するまで1回だけ）。Windows の通知も出る。ただし Microsoft のサインインごと切れているとメールは送れないので、`--status` の「最終実行」で確認できることも伝える。

## 4. 初回監査（既存の資料の取得）
定期監査を ON にする**前**に行う。すでに実施済み（`--status` の「初回監査」が「完了」）でも、**ダウンロード対象の講義を増やしたときは再度行う**（追加した講義の公開済み資料を取得するため）。

1. 学生に目的を説明する: 「今までに公開されている資料を一度取得し、全講義の現状を記録します。以降の定期監査は、ここからの“変化”だけを見つけます。」
2. **予行**を実行して、保存される資料を先に見せる。何も保存されない。
   ```powershell
   python -m src.main --initial-sync --dry-run
   ```
   - 講義ごとの件数と資料名が出る。「合計 N 件を `output/` に保存します。よいですか」と確認する。
   - 件数が多い／想定外の講義が入っている場合は、ステップ 2 に戻って対象を調整する。
   - 対象が 0 件（ダウンロード OFF など）の場合は、「保存はせず、現状の記録だけ行います」と伝える。
3. 了承を得たら**本実行**する。時間がかかることを伝える（1ファイルごとに間隔をあけて保存するため）。
   ```powershell
   python -m src.main --initial-sync
   ```
   - 結果メールは初回監査の報告として送られる（メール ON のとき）。送りたくなければ `--no-mail` を付ける。
4. 結果を学生に見せる: 講義ごとの保存件数と保存先（Teams が ON なら `Teams/` 以下も）、エラーの有無。学生に「`output/` を開いて、期待した資料が入っているか」確認してもらう。
5. エラーがあれば、原因を確認して `--initial-sync` をもう一度実行する（保存済みの資料は再取得されない）。**完了するまで定期監査を ON にしない。**

## 5. 確認と反映
1. `python -m src.main --status` を実行し、**設定の一覧を見せて**「この内容でよいですか」と確認する。「初回監査」が「完了」であることも確認する。違う項目があればその項目に戻る。
2. 定期監査を使うなら、ここで **`--check-on`** を実行して ON にする（初回監査が済んでいること）。
3. 定期監査を使うなら、**自動で動かし続ける方法**を案内して聞く。
   - `python -m src.main --install-task`（Windows にログオンすると自動で常駐。了承を得てから実行）
   - 登録した直後に始めたいときは PowerShell で `Start-ScheduledTask -TaskName YCUBoardWatcher`
   - 登録しない場合は、使うたびに `python -m src.main --watch` を実行する必要がある。
4. 最後に、設定の変え方（このスキル `/ycu-config` をいつでも呼べること、README の「設定を変える」）と、ログイン切れのときは `python -m src.main --login` を伝える。

## 設定の対応表
| 質問 | コマンド |
|---|---|
| 定期監査 ON / OFF | `--check-on` / `--check-off`（ON は初回監査の後） |
| 回数と時刻 | `--set-times HH:MM [HH:MM ...]` |
| 時刻の誤差（±10分） ON / OFF | `--jitter-on`（初期） / `--jitter-off` |
| 自動ダウンロード ON / OFF | `--download-on` / `--download-off` |
| ダウンロードする講義 | `--set-courses "講義名" ...`（引数なしで全講義） |
| Teams の講義資料 ON / OFF | `--teams-on` / `--teams-off` |
| クラウド保存（Google Drive など）| `--set-cloud-dir フォルダ` → `--test-cloud` → `--cloud-on` / `--cloud-off`（詳しくは `/ycu-cloud`）|
| 保存先 | `--set-output フォルダ` |
| メール ON / OFF | `--mail-on` / `--mail-off` |
| メールの頻度 | `--mail-always` / `--mail-changes-only` |
| メールの宛先 | `--set-mail-to アドレス` |
| 初回監査（予行 / 本実行） | `--initial-sync --dry-run` / `--initial-sync` |
| 自動起動 登録 / 解除 | `--install-task` / `--uninstall-task` |
